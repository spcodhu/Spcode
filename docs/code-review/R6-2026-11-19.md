## 2. 问题清单

### P1-1 · Task 子代理模型快照不随主会话刷新（已整改 ✅ 882a859）

- 位置：`apps/desktop/src/agent-host/tools/task.ts`（createAgentSession 的 model）、`session-controller.ts:393`
- 证据/触发：createTaskTool 闭包持有会话创建时的模型对象；refreshModelFromRegistry/setModel 只更新主会话
  `agent.state.model`。编辑自定义模型（如 systemMessageRole 改 system 修千问 developer 角色 400）后，
  主会话即时生效，但委派 Task 时子会话仍用旧对象 → 400 在委派路径复现。嵌套 `{...ctx}` 把旧对象传到所有深度。
- 影响：1832ee7 的核心目标在子代理路径落空；默认 prefer 档下读密集任务最常走 Task，命中概率不低。
- 修复：TaskToolContext 新增 `getModel` getter，spawn 时实时读 `session.model`（pi getter 直读 state.model，已核实引擎源码）；
  嵌套展开自动继承；创建时快照仅作缺省兜底，旧调用方行为不变。
- 验证：`test/task-model-refresh.test.ts` 双 fauxProvider 全链路真跑，断言子会话 createAgentSession 收到当前模型对象（去掉修复即红）。
- 置信度：高。

## 3. 值得保留的亮点（避免重构弄丢）

1. 「总允许」沉淀桌面/远程共用纯 helper：规则只信真实待决请求 + bypass 永不沉淀 / danger 只记 exact / 复合命令按段且需全段命中 / prefix 强制 token 边界，
   批准前同步原子落盘（0600），两端行为严格一致；危险命令移动端总允许同样走两步核对。
2. 协议新字段全部可选 + normalizePermissionMode 非法回落默认，新旧桌面/手机四种混用组合均安全降级且有单测锚定。
3. updater 七态闭环（checking/up-to-date/error.source）：侧栏对检查中间态静默、关于页内联反馈、共用 UpdateDialog 按 source 分流重试；手动检查不受 autoUpdate 开关限制。
4. 子代理请求级投影（transformContext 逐请求快照、保留段幂等替换、不写历史）与模型热刷新绕开 setModel（不写 model_change）的机制选对了；
   session-model-refresh / task-model-refresh 用真实 fs + fauxProvider 钉住回归。
5. pre-push tag 拦截覆盖普通推/--tags/--mirror/删除，仅 SPCODE_ALLOW_TAG_PUSH=1 放行；门禁 docs-only 尾巴判定经实跑双向验证（HEAD 拒、beta.41 过）。
