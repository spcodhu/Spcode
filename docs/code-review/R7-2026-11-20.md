## 2. 问题清单

### P1-1 · 折叠占位符对无来源证明的工具结果承诺了不可用的回读路径【已修复 f29cffb】
- 位置：`apps/desktop/src/agent-host/microcompact.ts:155-164`、`apps/desktop/src/agent-host/context-evidence.ts:172-186`、`wrapTool`（仅 read/edit/write 记录可验证来源）。
- 整改：`referenceEntry` 仅为有可验证来源证明的条目登记引用，其余返回 undefined；占位符无 ref 时改为“无自动回读来源”，仍禁止重跑。新增专项单测覆盖。
- 证据 / 触发条件：`findMicrocompactTargets` 对所有 ≥600 字符的旧 toolResult（含 bash/grep/find/ls/MCP）折叠；`maybeMicrocompact` 为每个目标 `referenceEntry` 登记引用并写入“Use ReadEvidence with ref …”占位符。但 `authorize` 要求执行时来源证明（provenance）：bash/powershell/MCP 未被 `wrapTool` 包裹（无 provenance 条目），grep/find/ls 的 provenance 标 `unverified-source`。对这些引用调用 ReadEvidence 一律返回 isError。
- 影响：模型被告知可回读，实际失败；bash 是工具输出体量最大来源（见 microcompact 头注），折叠后证据对模型实质不可恢复（原始 JSONL 与导出仍在，未丢数据）。属功能/体验缺口，非安全或数据损坏。
- 建议修复：二选一——(a) 仅折叠能登记可验证来源的条目，其余保留原文或折叠为不带 ref 的“不可回读”占位符；(b) `referenceEntry` 对无 provenance 条目返回 undefined，`placeholderText` 据此输出“证据不可自动回读，如需请重新读取源文件”而非 ReadEvidence 引用。倾向 (b)，改动小且不减少折叠收益。
- 置信度：高。

## 3. 值得保留的亮点（避免重构弄丢）

- 权限门禁经强制末尾扩展注入，普通与嵌套 `ctx.executeTool` 共用 `tool_call` 链并保留上游 veto；审批绑定最终参数摘要 + 策略版本，批准后重校验（`permission-extension.ts` / `permission-gate.ts`）。
- 危险/逃生舱仅 once、对外/复合仅 exact 的持久授权收紧；撤销递增 revision 使迟到回复失效（`agent-bridge.ts`）。
- 网络授权会话级 host:port、先唯一归因再查缓存、never 静默不沉淀（`sandbox/manager.ts`）。
- 证据回读分页按 UTF-8 字节不切断码点、跨分支/跨会话/兄弟任务拒绝、子任务证据销毁前持久化（`context-evidence.ts` / `read-evidence.ts`）。
- 子任务共享树预算原子预占 + 末票总结、写租约 FIFO + 持锁禁止等待写子任务（`task-runtime.ts` / `workspace-writer.ts`）。
- 升级前首次写设置自动备份副本（`settings-store.ts`）。
