## 2. 问题清单

### P1-1 · steering 消息误清空本轮子任务面板快照

- 位置：`apps/desktop/src/renderer/src/store.ts:778-779`；对照 `apps/desktop/src/agent-host/session-controller.ts:761-768`
- 证据：renderer 对**每条** `message_end(role=user)` 执行 `session.tasks = []`（注释自述"宿主每轮重开子任务树"）；但宿主侧运行中收到新 prompt 走 `session.steer()`，**不**重开任务树（`startMainPrompt` 仅在空闲新 prompt 时调用，task-runtime 注释明确 "not steering/continuation"）。主会话已复核 store.ts:779 属实。
- 触发条件：子任务运行中用户发送 steering 消息。
- 影响：①已完成子任务行/摘要从面板永久消失（终态事件只发一次）；②运行中任务在下个事件到来前面板闪空；③本轮 "N/M 完成" 计数失真。
- 建议修复：清空条件与宿主对齐——仅新轮 prompt 清空（依据会话运行状态或宿主下发轮边界事件）。
- 置信度：高（两侧代码证据齐全；现有测试未覆盖 steering 场景）。

### P1-2 · 子任务终态 failed/partial/blocked 路径零测试覆盖

- 位置：`apps/desktop/test/task-activity.test.ts:132-253`（`createTaskTool 活动事件全链路` describe 全部用例）
- 证据：仅 3 个 execute 用例——completed、嵌套 completed、外部 abort→cancelled；实现侧 task.ts:630-644 的 failed/partial/blocked 判定链无任何用例驱动断言。failed 路径用 faux `stopReason: "error"` 即可轻易模拟，属可测而未测。
- 影响：终态判定链回归（含 P2-1 的死条件）时现有测试全绿，UI 面板将显示错误终态或永远卡"运行中"。
- 建议修复：补 1 个失败终态用例，断言 `events.at(-1).status === "failed"`（或 partial/blocked）。
- 置信度：高。

### P2-1 · 子代理异常终态恒判 "partial"，"failed" 分支 error 条件为死条件

- 位置：`apps/desktop/src/agent-host/tools/task.ts:610-636`
- 证据：catch 块（610-613）把异常同时写入 `error` 与 `unresolved`；状态链 `run.stopReason || unresolved.length ? "partial"` 优先于 `error || ... ? "failed"`——error 命中时 unresolved 必非空，故 `error` 条件永不可达。主会话已复核状态链属实。
- 影响：子代理抛异常（如子会话创建失败）时面板显示"部分完成"而非"失败"，误导用户。
- 建议修复：error 命中且无产出/证据时判 "failed"，或把 error 判断置于 unresolved 之前（与 P1-2 补测联动）。
- 置信度：高（主会话复核；原判中，复核后上调）。

### P2-2 · 工具描述热切换依赖引擎"共享引用不拷贝"内部约定

- 位置：`apps/desktop/src/agent-host/session-controller.ts:663-676`
- 证据：`setSubagentMode` 就地改 `tool.description`，注释自述依赖引擎注册时不深拷贝 description。
- 影响：升级 pi 引擎若改为深拷贝，direct 档描述静默失效（off 档仍有工具集摘除兜底）。
- 建议修复：升级引擎时加单测锚定该行为。
- 置信度：中。

### P2-3 · 收起态下全终态时渲染空 padded 芯片容器

- 位置：`apps/desktop/src/renderer/src/components/WorkspacePanel.tsx:417`
- 证据：子任务全部终态且面板因其他原因可见时，chips 为空仍渲染带 padding 的容器，按钮下方留约 12px 空条。
- 建议：`chips.length > 0 || overflow > 0` 时才渲染。
- 置信度：高，影响低。

### P2-4 · 秒级定时器收起态持续运行；任务卡死时永不停止

- 位置：`WorkspacePanel.tsx:363-367`

- 建议：定时器条件加 `open`；卡死任务加 updatedAt 超时降级。
- 置信度：高，影响低。

### P2-5 · 每条 session.task 事件触发整面板重渲染

## 3. 值得保留的亮点（避免重构弄丢）

1. **终态发射系统性防挂起**：入口早退在 `emitActivity("queued")` 之前不留孤儿条目；终态在嵌套 finally 内先于 run.dispose/lease 释放发射，异常/中止路径也覆盖——"面板永远运行中"被结构性排除。
2. **wire 守卫单一来源**：TaskActivity/normalizeTaskActivity 定义于 `packages/shared/src/task-runtime.ts`，渲染层消费前强制归一化（长度截断、数值回退、status 白名单、depth 钳制），畸形载荷直接丢弃；`satisfies Record<keyof typeof zhCN, string>` 保证漏键即编译失败。
3. **测试质量高**：task-activity 用真实 ModelRuntime + fauxProvider 直驱（真跑子会话含并发槽/预算/证据链）；subtask-panel 用 jsdom + createRoot 真渲染覆盖可见性矩阵/交互/wire 拒收；subagent-mode 新断言与实现逐字对齐且经 fauxProvider 端到端验证。
4. **direct 档三处文案语义一致**（工具描述、policy 注入段、工具集摘除），全部宿主静态文本，无不可信输入拼接，未扩大注入面。
