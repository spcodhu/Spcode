## 2. 问题清单（含整改结果）

### P0-1 · 评审台账与 tag 提交自指死锁，门禁必然拦死每一次发版
- 位置：`scripts/release-gate.mjs:74`（严格 `reviewedCommit === target`）、`scripts/review-record.mjs:43,79`（`reviewedCommit = rev-parse HEAD`）
- 证据：台账只能在 HEAD=A 时写入；提交报告+台账必然产生 B≠A；tag 指向 B，CI 用 `--commit $GITHUB_SHA`=B 校验 → 恒失败。`git rev-list --count A..B`=1，只会提示「还有 1 个提交需要增量复评」，没有豁免分支。
- 影响：beta.40 及以后每次发版都会被 `review-gate` 拦掉（`needs` 使 build 不执行）。
- 整改：默认读**目标提交里的台账**（`git show <sha>:…`，`--worktree` 才读工作区）；允许 `reviewedCommit..target` 之间是「只改 `docs/code-review/**`」的尾巴（`merge-base --is-ancestor` + `git diff --name-only -z`），期间动过任何代码/测试就点名文件并要求复评；`reviewedCommit` 归一成 40 位 sha；`release.yml` 的 review-gate checkout 补 `fetch-depth: 0`。同步更新 `docs/code-review/README.md` 与 `AGENTS.md`。
- 置信度：高。

### P1-1 · 安全暂停清空排队消息＝静默吞掉用户插话
- 位置：`apps/desktop/src/agent-host/session-controller.ts:439`（整改前）、`apps/desktop/src/renderer/src/store.ts`（乐观气泡只靠引擎 ack 认领）
- 证据：`finishTurn` 早于 `getSteeringMessages()` drain，暂停那一刻队列里必然压着用户消息；`clearQueue()` 的返回值被丢弃，而这些消息从未落盘 → 重载后消失，UI 却留着乐观气泡。
- 影响：用户以为模型看到了，实际内容丢失且无提示。
- 整改：暂停时把 `clearQueue()` 返回的 steering/followUp 原文通过 `session.runGuard` 事件回传（`RunGuardPause.droppedSteering`）；渲染层摘掉未认领的乐观气泡、把原文与图片附件退回输入框草稿，暂停卡片显示「N 条插话已退回输入框」。纯图片插话（引擎队列只存文本）靠「未认领的乐观气泡」回收。补 `store.test.ts`（文本、纯图片、无丢弃三例）与 `run-guard.test.ts` 集成断言。
- 置信度：高。

### P1-2 · 同一门禁本地读工作区、CI 读提交
- 位置：`scripts/release-gate.mjs:31`
- 影响：本地 `record` 后不提交就能「通过」，提交后同一命令失败，本地自检结果不可作为发版依据。
- 整改：默认从目标提交读取台账与报告（`git cat-file -e`），`--worktree` 才读工作区；输出里显式打印「台账来源」。
- 置信度：高。

### P1-3 · 平滑回底标志会永久卡住「回到最新」按钮
- 位置：`apps/desktop/src/renderer/src/components/ChatView.tsx:33-44`
- 证据：初版用 `scrollingToLatestRef` 忽略动画期间的滚动事件，只以 `distance<8` 清除；用户用滚轮/触控板打断动画后，标志永不复位，之后所有滚动事件早退，按钮不再出现。
- 整改：改为 800ms 截止时间 window + 到点主动重量一次（`window.setTimeout(syncScrollState, 820)`），并且 `<8px` 时提前解除；阈值改为「<80px 自动吸底、≥80px 露出按钮」消除 80–159px 死区。
- 置信度：高。

### P1-4 · 被丢弃插话的图片/文件附件静默消失
- 位置：`apps/desktop/src/agent-host/session-controller.ts:443` + `store.ts` 退回逻辑
- 整改：图片从被摘掉的乐观气泡回填 `composerDrafts.attachments`；文件附件内容不在消息里（只有展示元信息），改为在草稿文本追加一行「以下文件附件未随插话发出，请重新添加：…」，且当回填文本已含 `<file>` 全文时不再追加，避免让用户重复添加。
- 置信度：高。

## 3. 值得保留的亮点（避免重构弄丢）

- 本地链接改「行内代码占位符 + `inlineCode` 还原」：链接留在原 Markdown 结构里（列表项/表格/引用块都成立），整段只用一个 Streamdown 实例，删掉了容易再次出错的分组逻辑。
- 右键菜单复用预览的路径守卫（`resolveWorkspaceFilePath` 只解析不读取、plan 目录 realpath 归一），菜单不成为任意路径出口。
- `review:context` 的「上下文包 + 只 grep diff」纪律，让本轮 10 提交/75 文件的评审没有把 diff 整体读进上下文。
- 门禁把「有没有做增量评审」变成机器可执行规则，且现在允许台账尾巴、拒绝代码尾巴。
