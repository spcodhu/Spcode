## 2. 问题清单

### P1-1 · 掩码密钥可跨协议/端点还原并发送
- 位置：`apps/desktop/src/renderer/src/components/SkillsPage.tsx:111-115,125-150`；`apps/desktop/src/main/index.ts:891-895`；`apps/desktop/src/main/settings-store.ts:320-324`。
- 证据 / 触发条件：切换协议、计费方式或自定义端点只改 `protocol/baseUrl/billing`，不清空 `apiKey`；`buildConfig()` 将掩码视为有效密钥。主进程测试和设置写回遇到 `SECRET_MASK` 时，无条件取当前已保存密钥，没有核对新配置是否仍属于原协议和实际端点。已保存千问配置后保留掩码并切换到自定义端点即可触发，直接 IPC 也可触发。
- 影响：原千问密钥会被还原并通过 `Authorization: Bearer` 发往新的自定义端点，形成凭据泄露与 confused deputy 风险。
- 建议修复：主进程将掩码绑定原配置身份，至少核对协议和实际请求端点；不一致时拒绝还原。UI 在协议、计费方式或端点变化时清空掩码，并补主进程回归测试。
- 置信度：高。

### P1-2 · 图片下载缺少 SSRF 防护与逐跳重定向校验
- 位置：`packages/shared/src/image-gen.ts:165-175,338-351`；落盘点 `apps/desktop/src/agent-host/tools/image-gen.ts:87-93`。
- 证据 / 触发条件：响应路径得到的字符串只要以 HTTP(S) 开头就直接 `fetch(url, { redirect: "follow" })`；没有主机/IP/DNS 校验，重定向也不会逐跳复检。服务可返回 localhost、私网、链路本地/metadata 地址，或由公网 URL 重定向到这些地址。仓库已有 `apps/desktop/src/agent-host/tools/ssrf.ts` 可复用。
- 影响：桌面端可被诱导请求本机或内网服务，响应还会写入工作区，存在内部服务操作和本地数据暴露风险。
- 建议修复：复用现有 SSRF 能力，校验公网 HTTP(S)、DNS 解析结果和每一跳重定向；本机图片服务如确有需要，应显式 opt-in。
- 置信度：高。

### P1-3 · 中断或异常退出会留下永久“正在生成”卡片
- 位置：`apps/desktop/src/renderer/src/components/MessageItem.tsx:514-516`；`apps/desktop/src/renderer/src/store.ts:424,946-951`。
- 证据 / 触发条件：等待卡片只看 `c.status === "running"`，不检查当前回合 `active`；历史回放缺少 `toolResult` 时会把调用还原为 `running`；`agent_settled` 只结束消息流，不结清工具调用。用户中止未收到 `tool_execution_end`，或应用在结果持久化前退出/崩溃即可触发。
- 影响：回合已结束，画廊仍永久显示等待卡片并持续计时；并行调用中单个缺失结果的调用也会悬挂。
- 建议修复：等待卡片至少增加 `active` 条件，并在回合结束或历史回放时将孤立 `running` 调用归一化为中断/失败终态；补 abort 与历史回放测试。
- 置信度：高。

### P1-4 · Windows 主程序改名后，旧开机启动登录项未迁移
- 位置：`apps/desktop/electron-builder.yml:2`；`apps/desktop/src/main/login-item.ts:58-61`；`apps/desktop/src/main/index.ts:703-704,976`。
- 证据 / 触发条件：`productName` 从 `Spcod` 改为 `Spcode`，且未固定 Windows `executableName`，主程序会由 `Spcod.exe` 改为 `Spcode.exe`。登录项只在用户调用 `setEnabled()` 时重写，启动流程没有重新登记或清理旧路径。beta.43 已开启开机启动的用户覆盖安装或自动升级后可能触发。
- 影响：旧 Run 登录项可能指向已删除的 `Spcod.exe`，导致升级后不再开机启动；旧目录保留时也可能启动旧版本。未打包 E2E 覆盖不到该路径。
- 建议修复：暂固定 Windows `executableName` 保持旧路径，或增加首次启动迁移并避免误重新启用用户主动停用的项目；补 beta.43 → beta.44 Windows 实机升级验证。
- 置信度：中高（0.80）；静态路径明确，注册表实际残留形态仍需 Windows 实机核实。

### P2-1 · 25MB 下载上限在完整读入内存后才判断
- 位置：`packages/shared/src/image-gen.ts:169-171,205`。
- 证据 / 影响：先 `arrayBuffer()` / `text()` 完整读取，再检查大小；超大或持续 chunked 响应仍先占满内存，base64 还会放大占用，可能卡顿或 OOM。
- 建议修复：Content-Length 预检 + 流式累计上限，超限立即取消；JSON 与 inline base64 同样限长。
- 置信度：高。

### P2-2 · 已取消的 AbortSignal 不会取消随后发起的生图请求
- 位置：`packages/shared/src/image-gen.ts:409-415`；`apps/desktop/src/agent-host/tools/image-gen.ts:82-93`。
- 证据 / 影响：只注册 abort 监听，未处理 `signal.aborted`；预先取消的信号不会再次派发事件，仍可能发起付费请求并落盘。
- 建议修复：安装监听前处理预取消，落盘前再检查；补 pre-aborted 与请求中取消测试。
- 置信度：高。

### P2-3 · 多图下载一个失败后，其余下载脱离超时与取消管理
- 位置：`packages/shared/src/image-gen.ts:351,406-438`。
- 证据 / 影响：`Promise.all` 任一拒绝后 `finally` 清除超时和外部 abort 监听，却没有 abort 同组其余请求；慢请求可能在工具返回失败后继续占连接和内存。
- 建议修复：失败时主动取消同组请求，或 `allSettled` 等待收尾；补“一失败、一悬挂”测试。
- 置信度：高。

### P2-4 · 未验证实际位图内容，非图片可作为成功结果落盘
- 位置：`packages/shared/src/image-gen.ts:134-139,169-175`。
- 证据 / 影响：Data URL 只信声明的 `image/*`；下载响应也信任声明 MIME，未知魔数默认当 PNG。HTML/文本错误页或伪 base64 可被报告为成功，最终由 UI 加载失败。
- 建议修复：解码后校验支持的位图魔数及声明 MIME 一致性，非法内容报错且不落盘。
- 置信度：高。

### P2-5 · 自定义 Body 的 prompt 校验可被对象键中的占位符绕过
- 位置：`packages/shared/src/image-gen.ts:245,251-260`。
- 证据 / 影响：校验只搜索原始模板是否含 `{{prompt}}`，实际替换只递归对象值；仅占位符在 key 中时配置显示 ready，但请求没有生图描述。
- 建议修复：在解析后的 JSON 值节点检查有效 prompt 占位符，补仅 key 含占位符的拒绝测试。
- 置信度：高。

### P2-6 · 旧测试生成结果可覆盖停用或后续编辑后的状态
- 位置：`apps/desktop/src/renderer/src/components/SkillsPage.tsx:154-183`。
- 证据 / 影响：测试只捕获开始配置，返回后无条件 `setPreview()` / `flash()`；保存、停用和编辑不使在途请求失效，可能在停用后仍显示“生成成功，配置可用”。
- 建议修复：请求序号或配置指纹使旧结果失效；如需真正停止计费请求，再增加 IPC 取消链路。
- 置信度：高。

### P2-7 · 保存、停用和测试的 Promise 拒绝没有用户可见错误
- 位置：`apps/desktop/src/renderer/src/components/SkillsPage.tsx:154-183`；`apps/desktop/src/renderer/src/store.ts:1924-1933`。
- 证据 / 影响：操作缺少 `catch`，按钮用 `void` 调用；设置写盘或 IPC 拒绝会产生未处理 rejection，用户无法判断配置是否落盘。
- 建议修复：外层捕获并显示可显式关闭的错误，测试仍在 `finally` 复位等待状态；不得输出配置或密钥。
- 置信度：高。

### P2-8 · 自定义端点只校验非空，非法地址也显示已配置
- 位置：`apps/desktop/src/renderer/src/components/SkillsPage.tsx:125-150`；`packages/shared/src/image-gen.ts:60-80`。
- 证据 / 影响：表单和 readiness 只检查 `baseUrl.trim()` 非空；`foo`、`http://` 等也会保存并激活工具，直到调用才失败。
- 建议修复：表单和共享 sanitize/readiness 统一用 `new URL()` 校验并限制 HTTP(S)，保留明确的本地 HTTP 测试能力。
- 置信度：高。

### P2-9 · 多图异步加载会让灯箱无操作切换到另一张图片
- 位置：`apps/desktop/src/renderer/src/components/GeneratedImageGallery.tsx:33,43-59,80-84`。
- 证据 / 影响：灯箱只保存 `previewIdx`，图片加载完成后数组顺序/下标会变化；用户打开 B 后，排在前面的 A 加载完成会让下标指向 A，并重置缩放。
- 建议修复：以图片路径作为预览状态，再推导当前下标；补前序图片后加载的回归测试。
- 置信度：高。

### P2-10 · 每秒更新的等待时间位于 polite live region
- 位置：`apps/desktop/src/renderer/src/components/ImageGenProgress.tsx:26,32-34,54-55`。
- 证据 / 影响：整个卡片是 `role="status" aria-live="polite"`，秒数每秒更新，屏幕阅读器可能持续播报并干扰操作。
- 建议修复：静态状态进入 live region，可见计时移出或设 `role="timer" aria-live="off"`。
- 置信度：高。

### P2-11 · 工作区分隔条测试用键盘替代了真实 Pointer 拖拽
- 位置：`apps/desktop/e2e/appearance.spec.ts:100,111-118`。
- 证据 / 影响：全平台都从 `drag()` 改为键盘 ArrowRight；Pointer Capture、pointermove/up 回归时仍可能全绿，用例名却仍称“可拖动”。
- 建议修复：保留真实 Pointer 路径，键盘微调作为额外覆盖；Windows 应修坐标/捕获问题或明确记录产品缺陷。
- 置信度：高（覆盖缺口，不代表当前实现已失效）。

### P2-12 · “完全退出”E2E 绕过真实按钮动作性并吞掉全部异常
- 位置：`apps/desktop/e2e/window-chrome.spec.ts:145-153`。
- 证据 / 影响：`dispatchEvent("click")` 不检查可见、启用、遮挡和实际点击位置；`.catch(() => {})` 丢弃全部异常。退出结果断言仍有效，但用户点不到按钮时也可能通过。
- 建议修复：先断言可见/启用并优先真实 click，仅定向容忍已退出后的 Target closed 错误。
- 置信度：高（覆盖缺口）。

### P2-13 · 品牌改名后，README 与签名文档仍引用旧产物路径
- 位置：`README.md:34`、`README.en.md:34`、`docs/code-signing.md:294,315,530,555-556`；对照 `apps/desktop/electron-builder.yml:2,49`。
- 证据 / 影响：文档仍使用 `Spcod.app`、`Spcod.exe`、`Spcod-Setup-*.exe`，新包为 Spcode；用户解除隔离命令和维护者签名验收会找不到目标。
- 建议修复：同步所有路径和匹配模式，并在升级说明记录 `.app`、`.exe`、安装包和快捷方式名称变化。
- 置信度：高。
